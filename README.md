# E-VIVLIO

The existing Patricia & Patrick 3D cottage is the front door to four applications on **one origin, one account, one PostgreSQL database**.

| Entrance | URL | App |
|---|---|---|
| Carl sticker | `/folio/` | Shared PDF/EPUB reading |
| Russell sticker | `/lib/` | Book and article search |
| Dug sticker | `/yard/` | Music search and shared listening |
| House | `/cove/` | Peer-to-peer video calls |
| Shared menu | `/account` | Private search history and recently visited room links |

## Run locally

Use Node 22.12 or newer (the version in `.node-version` is the tested deployment target).

```sh
npm ci
npm run build
npm run dev
```

The gateway listens at `http://localhost:4400`. All worker servers bind only to loopback. `npm run build` installs and builds the existing apps. `npm start` serves those production builds. The dev command uses their Vite servers.

Without `DATABASE_URL`, **one disk-backed PGlite database** is created under `.data/postgres`. A private, randomly authenticated loopback service lets Folio and Yard use that same instance. Data survives restarts; local development sessions are invalidated on restart unless `BETTER_AUTH_SECRET` is supplied. Never run two copies against the same `.data` directory.

## Render + Neon deployment

`render.yaml` defines one Node web service for the gateway, four apps, and Cove's Socket.IO signaling server. Set these server-side environment values in Render:

- `DATABASE_URL`: the **same Neon PostgreSQL connection URL** for the entire service. Use the connection string with TLS options supplied by Neon. Never use a `VITE_` prefix.
- `APP_URL`: optional on Render, which supplies `RENDER_EXTERNAL_URL` automatically. Set this to the exact HTTPS origin (no trailing slash) when using a custom domain.
- `BETTER_AUTH_SECRET`: generated by the blueprint. Keep it stable across deployments.

The start command applies additive migrations before serving traffic. Production refuses to start without the database or a stable auth secret. `TRUST_PROXY=1` is appropriate behind Render's single public ingress; do not enable it when exposing the Node port directly.

Render supports inbound WebSockets: https://render.com/docs/websocket . This is why the default deployment uses a running Node service. Do not deploy the whole ecosystem as Vercel static files or short-lived functions: Cove's Socket.IO process and the worker supervisor need a persistent server. A Vercel deployment would need an adapted process lifecycle, signaling-state handling and deliberate routing/cookie configuration; the supplied deployment configuration targets Render.

No hosted database or public deployment has been provisioned by this repository. Supply the above values in your hosting account before publishing.

## Data and security

- Better Auth handles email/password hashing, HttpOnly session cookies, sign-in/out, origin checks, and auth rate limiting. All four apps’ pages, APIs, uploaded documents, and Socket.IO require that same session. Public hashed JavaScript/CSS bundles are served separately with long-lived caching.
- The gateway derives the user from the verified session. Search-history and room-history reads, writes, and deletion are always scoped to that user. Browser-supplied user IDs are ignored.
- Lib saves deliberate submitted searches; Yard saves a query after the user pauses typing. Every saved search is recorded in ecosystem_search_events, including repeat queries, while ecosystem_searches maintains the recent-history list. Clearing history removes both for that user. The account screen can reopen a search and clear history. Lib's clear button removes only Lib history.
- Folio retains its existing room, document, chunk, reader and note tables. Yard retains its existing signaling/presence tables. The new account, session, search and room-index tables share the same database. No extra Supabase database is required.
- Room codes are shareable invitations for signed-in users, not private vaults. Folio host permissions use its existing random host key; that key is stored in the database and the creating browser. Room history keeps room links, not a durable live call or an entire listening session.
- Cove media and chat remain peer to peer. Persisted room links are independent of the in-memory active signaling roster. Calls need HTTPS and browser camera/microphone permissions; some networks also need a TURN service. Those conditions have not been tested across remote devices here.
- Existing music and book providers remain external dependencies. Catalog availability and playable audio depend on those providers; failed requests display their app's error state. Yard's existing provider configuration can be supplied through server environment variables (`AUDIOMACK_CONSUMER_KEY` and `AUDIOMACK_CONSUMER_SECRET`).
- Email delivery/password recovery and email ownership verification are not configured. Do not advertise those workflows until a mail provider is connected.
- Keep `.data`, secrets, and dependency/build folders out of version control. `.gitignore` covers them.

## Verification

```sh
npm test
npm --prefix lib-main run typecheck
npm --prefix folio-room-main run typecheck
npm --prefix yard-main run typecheck
```

The API integration suite creates real test accounts in an isolated in-memory database and verifies session protection, per-user isolation, input validation, cross-origin rejection, search deletion, room history, and logout revocation. Tests do not touch local user data.

Folio, Yard, and Lib retain their standalone build defaults. Cove is now mounted at `/cove/`, and the cottage links expect the shared gateway, so use the root scripts for the full website. Set `ECOSYSTEM=1` for Folio/Yard's Node-server builds and the `/folio/`, `/yard/`, `/lib/` base paths; the root scripts do this automatically. Original Grok-specific auth helpers remain untouched: ecosystem authentication is enforced centrally by the gateway, not by a second login in each app.

### Moving between apps without stopping media

The gateway serves a persistent workspace for normal browser navigation. Each
visited app keeps its own same-origin frame. Use the **E-VIVLIO / your places**
menu, cottage links, or the small player to switch apps. Returning to the cottage
reuses its loaded 3D scene; the welcome step is also remembered for this tab.

An active Cove room shrinks into a bottom-right panel with the remote participant and an inset self-preview for two-person calls,
microphone/camera controls, Leave, and Open Cove. Enable devices in the lobby when
needed; joining without devices is supported. Yard keeps its audio engine and
room synchronization alive, and provides a persistent track/play-pause control.
Returning to Cove or Yard restores the current room. Leave a Cove call before
opening a different Cove room. Sign-out unloads the workspace and its sessions.

Continuity applies while moving inside this workspace. Reloading/closing the tab,
opening a separate tab, browser suspension, and network loss do not preserve a
live call. Actual cross-device camera/microphone quality and timing still require
real-device testing; production Cove connectivity may need TURN on strict networks.


### Shared group chat and room notifications

Open **Group chat**, create a group, and share its code once. Other signed-in
members join with that code. Messages stay available while switching between
apps, and newly opened rooms appear as cards with an **Open room** button.
Other members also see an in-app **Join** notification. Updates arrive within
about eight seconds while the page is visible. Each account joins one group at a
time; group members can read recent group history. This does not automatically
join calls or enable anybody's camera or microphone.

The cottage stops rendering when hidden. Cove uses lower-resolution camera
capture, serializes signaling, queues early ICE candidates, and rebuilds peers
after signaling reconnects. See DEPLOYMENT.md for optional TURN relay setup.
